## 宿題

- 取り組んだレベル：基礎

- やったこと：
  - app/tools.py の search_glossary の docstring を変更した。
  - 「query には調べたい用語を1つだけ入れる」という指示を、比較対象の用語をまとめて入れ、1回で検索する指示に変更した。
  - 同じモデル（gemini-3.5-flash-lite）に、変更前後で「LoRAとQLoRAの違いは？」を --trace 付きで質問し、動作を比較した。

- 結果：
  - 変更前は、以下のように用語を個別に検索していた。
    - search_glossary({'query': 'LoRA'})
    - search_glossary({'query': 'QLoRA'})
  - 変更後は、以下のように2つの用語をまとめて検索していた。
    - search_glossary({'query': 'LoRA QLoRA'})
  - tool_calls は2から1に減ったが、requests はどちらも2だった。ツールの呼び出し回数が減っても、LLMの呼び出し回数は変わらなかった。
  - 入力トークン数は1350から1061に減少し、出力トークン数は174から179に微増した。
  - ログ上の cost は0.0008400から0.0007658に減少した。
  - 最終回答の表現には違いがあったが、どちらもLoRAとQLoRAの違いを説明し、「関係する回：第2回」と表示していた。
  - 変更後のツールの戻り値は途中で省略されているため、検索結果に両方の用語が含まれていたかまでは確認できなかった。

- 気づき・疑問：
  - 今回は、検索処理のコードを変えずに、モデルに渡す説明文を変えることで、ツールの引数と呼び出し回数が変化した。docstring がモデルのツール利用の判断に影響することを確認できた。
  - 1回のLLM呼び出しで複数のツール呼び出しを要求できるため、tool_calls と requests は別に考える必要があると分かった。
  - 今回は入力トークン数と cost が減ったが、説明文自体も変更しているため、すべてが検索回数の減少によるものとは断定できない。
  - 検索をまとめても必要な情報を取得できているか、戻り値の全体を確認したい。また、繰り返し実行しても同じ傾向になるかを確かめたい。
